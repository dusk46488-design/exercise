### Agenda & Discussion

1. **Data quality assessment.** The group loaded the generated `rs3_tests.csv` (320 rows) and verified the data volumes: 33 of 320 test scores (10.31%) were missing, concentrated in the `daily` condition (15.0% vs. 5.6% for `spaced`), reflecting the higher attrition probability assigned to daily-review participants. The group confirmed these figures match the generator's injection parameters.

2. **Filter strategy comparison.** The group reviewed three filtering approaches applied via `0203.py`:
   - **DropFilter (complete-case deletion):** Removes any row with NaN/infinite/empty values. Retains 287 rows (−10.3%). Justified by Schafer (1999): under MCAR with < 5% missingness, complete cases are an unbiased random subsample. However, the 10.3% exceeded the 5% threshold.
   - **HeuristicFilter (median/mode substitution):** Preserves all 320 rows but replaces missing values with column median/mode. The median is chosen for its 50% breakdown point (Rousseeuw & Hubert, 2011), making it robust to ex-Gaussian RT skew.
   - **ImputationFilter (hot-deck):** Draws replacements via random sampling with replacement from observed values. Non-parametric — preserves empirical distribution without parametric assumptions (Andridge & Little, 2010).

3. **Completeness metrics.** The group discussed using Shannon entropy (Cover & Thomas, 2006) as a quantitative measure of information preservation across filter stages. Entropy was computed via binned histogram estimation with 20 bins.

### Decisions

- [ ] Chain filters: `drop` first to remove incomplete rows, then `imputation` to fill remaining gaps
- [ ] Use Shannon entropy as the primary information-preservation metric

### Discussion Summary

1. **Filter plugin architecture.** Discussed implementing the `FilterPlugin` ABC with three concrete subclasses in `0203.py`:
   ```python
   class FilterPlugin(ABC):
       @abstractmethod
       def apply(self, df: pd.DataFrame) -> pd.DataFrame: ...
   ```
   Filters are chainable via CLI: `-f drop -f imputation` first removes incomplete rows, then imputes remaining missing values. The `--list` flag exposes the plugin registry.

2. **HeuristicFilter design decisions.** Discussed why median (not mean) for numeric imputation: the 50% breakdown point makes it robust to the right skew of ex-Gaussian RTs. Mode for categoricals. The trade-off: single imputation systematically underestimates variance (Little & Rubin, 2019, Ch. 4) — all imputed values are set to the same point, creating an "imputation spike" in the distribution.

3. **Hot-deck imputation approach.** Discussed the algorithm: (1) identify complete-case donor pool for each column, (2) draw `n_missing` samples with replacement, (3) assign to missing positions. Falls back to median/mode when no complete cases exist. Key advantage: preserves the empirical distribution, including skew and boundedness. Key assumption: donor pool is exchangeable with recipient pool — satisfied under MCAR, violated under MNAR.

4. **Entropy as a completeness metric.** Discussed Shannon entropy H(X) = −Σ p(x) · log₂ p(x) computed via histogram binning. Entropy quantifies distributional spread: higher entropy = more uniform distribution, lower entropy = more concentrated. The 3.75% entropy reduction from heuristic imputation (4.00 → 3.85 bits) quantifies the information loss from concentration at the median.

5. **Filter comparison results preview.** The group discussed the expected trade-offs:

   | Metric | Raw | Drop | Heuristic | Hot-Deck |
   |--------|-----|------|-----------|----------|
   | Rows | 320 | 287 | 320 | 320 |
   | Missing retained_score | 33 | 0 | 0 | 0 |
   | Std | 25.19 | 25.19 | 23.41 | 25.19 |
   | Entropy (bits) | 4.00 | 3.98 | 3.85 | 3.98 |

   The drop filter preserves distribution exactly but loses rows; the heuristic filter preserves rows but creates an imputation spike and variance underestimation; hot-deck preserves both rows and distribution shape.
