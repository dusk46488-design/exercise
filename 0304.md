### Agenda & Discussion

1. **Descriptive statistics review.** The group ran `0204.py` with `DescriptivePlugin` on the filtered dataset, grouped by `condition`. Key observations:
   - Mean retention: spaced = 64.3, daily = 48.1 — consistent with the hypothesised spacing effect
   - RT skewness: positive skew in both conditions, confirming the ex-Gaussian τ tail
   - JOL overconfidence: daily group mean JOL exceeded mean retention by ~5.6 points (matching the +5 bias parameter)

2. **Outlier detection.** The group compared two methods:
   - **IQR-fence method (Tukey, 1977):** No outliers detected in `retention_score` — scores are well-behaved within [0, 100]
   - **Z-score method (|z| > 3):** Zero outliers in `retention_score` — confirms approximate normality of conditional distributions
   - Discrepancy between methods would signal heavy tails; the agreement here confirms the data is well-behaved

3. **Normalisation strategy.** The group compared three normalisation filters:
   - **Z-score ((x − μ) / σ):** Affine transform — preserves distributional shape exactly, but outlier-inflated σ compresses bulk data
   - **Min-max ((x − min) / (max − min)):** Most outlier-sensitive — a single extreme RT determines the max, compressing all other values
   - **Robust ((x − median) / IQR):** Recommended for ex-Gaussian data — 50% breakdown point (Rousseeuw & Hubert, 2011), centres at 0 with IQR-scaled dispersion while keeping extreme RTs visibly separated

4. **Analysis plugin architecture.** The group reviewed the `AnalysisPlugin` ABC hierarchy alongside the extended `FilterPlugin` normalisation subclasses. Discussed whether normalisers should be filters (transforming data) or analysers (reporting on data). Decided to keep them as `FilterPlugin` subclasses since they transform the data in preparation for downstream modelling.

### Decisions

- [ ] Primary normalisation: Robust scaling for ex-Gaussian RT data
- [ ] Outlier detection: report both IQR and Z-score methods side-by-side
- [ ] Descriptive statistics: grouped by `condition` for primary analysis

1. **DescriptivePlugin design.** Discussed the `analyze(df, columns=None, groupby=None) → dict` contract. Outputs: count, missing count, missing %, mean, median, std, min, max, skewness, excess kurtosis — per column, optionally grouped by a categorical variable. Used `StatsHelper` for edge-case-safe functions (`safe_skew`, `safe_kurtosis`) that handle constant columns and single-value columns without throwing exceptions.

2. **OutlierPlugin design.** Discussed implementing two detection methods side-by-side:
   - **IQR fence:** lower = Q1 − 1.5·IQR, upper = Q3 + 1.5·IQR
   - **Z-score:** |(x − μ) / σ| > 3
   - Reporting both lets the analyst cross-validate: discrepancies between methods signal distributional features (e.g., heavy tails) that neither method alone would reveal.

3. **Normalisation filter comparison.** Discussed the theoretical properties of each normaliser:
   - Z-score: entropy unchanged (affine), skewness and kurtosis preserved — but σ is inflated by ex-Gaussian τ tail
   - Min-max: bounded [0, 1], but range determined by extremes — one outlier compresses all other data
   - Robust: centres at median, scales by IQR — 50% breakdown point means up to half the data can be contaminated without affecting the transformation

4. **CompletenessPlugin extension.** Discussed extending the Day 3 completeness analysis with:
   - Per-column missing-data overview
   - Pearson correlation matrix (with annotations for |r| > 0.7)
   - Shannon entropy per column (histogram estimator, 20 bins)
